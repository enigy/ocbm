OCBM 2.6.5: an update package for adapters on OCBM 1.0.1 to 2.6.1, once their install is final. Wireless CarPlay connects sooner: on the bench, with Carlink 3.25, a wake reached the picture in 5.2 to 6.4 s with the iPhone in use (16 wakes), where the same iPhone took 8.2 to 9.4 s on 2.6.1. With the iPhone locked and idle it took 5.2 to 8.8 s (5 wakes).

- **Bluetooth ready before Carlink arrives.** Between sessions the adapter keeps Bluetooth powered but invisible: not discoverable, not connectable, no links, and no Wi-Fi access point. When Carlink arrives, the adapter calls the phone about 0.1 s later, instead of about 1.2 s. If that start fails, the adapter powers Bluetooth afresh, as 2.6.1 does at every connect. To turn it off, create the file /script/radio_arm_off on the adapter.
- **The Wi-Fi access point sooner.** Its configuration is written ahead and it is launched first, so it is up about 1.2 s after Carlink arrives, instead of about 2.0 s. It runs only during a session, as before.
- **The CarPlay receiver starts with the session.** carplayd starts as the Bluetooth session begins, not after the Wi-Fi details are sent, and dials the phone as soon as the adapter has sent it those details.
- **The chip's certificate, read once.** The authentication chip's certificate is read once after the adapter powers up and kept for later connects; each connect read it twice, 0.11 to 0.17 s a time. A failed authentication drops the kept copy.
- **Fixed: the adapter's Wi-Fi with no address server.** In 2.6.0 and 2.6.1 a session's access point could take the last session's DHCP server, still exiting, for its own, and leave the phone on the Wi-Fi without an address for several seconds. The teardown now waits for that server, and a new access point never counts it.
- **The `[timeline]` line.** Two more keys: `bt_armed` (1 when the connect started from the armed state) and `dial_ok` (when the receiver was free to dial). The line is at most 827 bytes and still names no phone. docs/ops/02_TESTING.md lists the keys.

**From 2.6.1 and 2.6.0, for adapters on 2.6.0 or older** (they update straight to 2.6.5):

- **A `[timeline]` line for each connect** (2.6.1). At the first video frame of a wireless connect the adapter logs the time of each step since Carlink arrived, and how long the authentication chip took. Carlink keeps the line with its own times while Record drive logs is on.
- **A change of phone in about 5 s** (2.6.0). When an iPhone other than the last session's connects, it reaches the CarPlay picture about 5 s after it joins the adapter's Wi-Fi, instead of 40-90 s.
- **The Wi-Fi password** (2.6.0). An adapter that goes back to stock in its install trial keeps the Wi-Fi password OCBM gave it for the next install, and an install from stock takes over the adapter's own password whole.

Releases v2.6.1 and v2.6.0 say more. Adapters on 2.0.0 or older also get 2.5.0's faster wireless connects and boot preload (release v2.5.0), and adapters on 1.0.x get 2.0.0's changes too: video from the iPhone while parked, the car's GPS and status for the iPhone, and one name for the adapter's Wi-Fi and Bluetooth (release v2.0.0).

The package changes 17 files (btd, carplayd, iap2d, iap_role_switch, ocbmd and 12 scripts) plus etc/ocbm/retired.list, counted against every published version from 1.0.1 to 2.6.1. Against 2.6.1 it changes btd, carplayd and five scripts (ocbm_boot.sh, ocbm_dispatch.sh, radio_ap_up.sh, radio_hal.sh, session_supervisor.sh). It needs about 3281 KB of flash while it runs, so it does not fit a trial: an adapter still in its trial finishes its install first (in Carlink: Settings › Adapter and about › Remove stock CarPlay), then takes the update. Updates from 1.0.1 (FROM_MIN 1.0.1). Built from enigy/ocbm 1974bb0 ("2.6.5 ocbm 1974bb0"); iap2d and iap_role_switch, whose programs are unchanged, are 2.0.0's builds, as in 2.6.1.

Install it from Carlink 3.25 (Settings > Adapter and about), or put ocbm-update-2.6.5.tgz and its .sha256 on a USB stick and start the adapter with it in. The installer image for a stock adapter is on release installer-2.6.5.

Going back to stock from a finished adapter wipes its paired phones: forget the adapter (CarLink-xxxx) on each phone first, and pair them again afterwards.

No update is guaranteed to succeed. The update runs as a trial and falls back to the version it replaced if its self-test fails, the adapter never answers Carlink, or its Bluetooth never comes back.
